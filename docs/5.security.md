# Security Specification

## 1. General Principles

A portfolio is mostly public content, but any dynamic functionality must be secured properly.

---

## 2. Environment Variables

Never commit:

```text
.env
.env.local
```

to GitHub when they contain secrets.

---

## 3. Contact Form

If a contact form is implemented:

Validate:

- Name
- Email
- Message

Protect against:

- Spam
- Injection
- Malicious input
- Excessive requests

---

## 4. API Security

If a backend is introduced:

- Validate all requests
- Sanitize inputs
- Implement rate limiting
- Use HTTPS
- Keep secrets server-side
- Return safe error messages

---

## 5. Dependencies

Dependencies should be:

- Kept updated
- Audited regularly
- Removed when unnecessary

---

## 6. Sensitive Information

Never publish:

- Passwords
- API keys
- Private tokens
- Database credentials
- Private personal documents
- Private user information

The public repository should contain only information intended for public access.
